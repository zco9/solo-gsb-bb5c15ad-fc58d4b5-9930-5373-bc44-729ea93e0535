# 纸张对折打孔展开预览

在浏览器里设定一张纸的宽高，按顺序指定若干次**沿当前纸张水平/垂直中线的对折**
（并指定哪一侧折向另一侧），然后在最终折叠面上点击打一个或多个孔。
程序按折叠顺序**逆推**每个孔穿透各层后在原纸上的全部位置，并排实时显示
**折叠面**与**展开图**（原生 SVG），并支持下载展开图 SVG 文件。

也可以用**反查打孔**：直接在展开图上点击原纸目标孔心，服务端按当前折叠顺序
及折向逐层折回最终折叠面，返回归一化孔心并高亮这一次打孔必然生成的全部
连带孔位，确认后才加入现有打孔点（与在折叠面点击完全等价）。

还可以划定**原纸保护区**：用毫米坐标录入至多 8 个轴对齐矩形（禁打孔区域），
展开图中以绿色虚线框标出。任一展开孔圆与任一保护区相交或相切即违规，
系统指出原打孔点、触碰的展开孔及保护区，不生成展开图、禁止下载；
反查打孔的待确认结果执行同一判定。

- 后端：Python + Flask（计算与 SVG 生成均在服务端，结果唯一可复现）
- 前端：原生 HTML / JavaScript / 内联 SVG，无任何前端构建与 CDN 依赖
- 部署：Docker + Compose，一条命令完成依赖安装与启动

## 一条命令启动

需要本机已安装 Docker 与 Docker Compose 插件（Docker Desktop 自带）。

```bash
docker compose up --build
```

首次执行会构建镜像并安装 `requirements.txt` 中的依赖，之后启动 Web 服务。
启动成功后浏览器访问：

```
http://localhost:8000
```

后台运行用 `docker compose up --build -d`；停止用 `docker compose down`；
查看日志用 `docker compose logs -f`。

## 配置（均为可选）

通过环境变量或项目根目录的 `.env` 文件覆盖，无需修改代码：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `HOST_PORT` | `8000` | 宿主机映射端口（只想换访问端口时改它，例如 `HOST_PORT=9000`） |
| `PORT` | `8000` | 容器内监听端口 |
| `MAX_FOLDS` | `8` | 最多对折次数 |
| `MAX_HOLES` | `24` | 折叠面上最多打孔点数 |
| `MAX_ZONES` | `8` | 原纸上最多保护区个数 |

例：换到 9000 端口

```bash
HOST_PORT=9000 docker compose up --build
# 访问 http://localhost:9000
```

纸张宽高范围 20–2000 mm，打孔半径 0.5–50 mm（同样可在 `app.py` 顶部调整）。

## 使用说明

1. 输入纸张宽度 W、高度 H 与打孔半径 r（单位 mm），或点 A4 等预设。
2. 用四个按钮依次添加折叠：
   - **垂直对折 · 右折向左**：沿竖直中线，右半翻到左半上（左半不动）
   - **垂直对折 · 左折向右**：左半翻到右半上（右半不动）
   - **水平对折 · 上折向下** / **下折向上**：沿水平中线，含义类似
   每条折法可单独删除，顺序即折叠顺序。
3. 在折叠面（左视图）的**绿色虚线安全框**内单击打孔；单击已有孔可删除；
   修改宽高、半径、折法或孔位后，展开图即时重算。
4. **反查打孔**：点展开图下方的「反查打孔」开关后，在展开图上单击目标孔心。
   服务端把该点按当前折法逐层折回折叠面，返回归一化孔心，并用同一展开算法
   列出本次打孔必然生成的全部孔位：黄色高亮为连带孔位、蓝圈为目标孔，
   折叠面上同步标出反查到的打孔位置。点「确认加入打孔点」后才真正加入
   （之后与手点孔一样参与展开与 SVG 下载）；「取消」或改变纸张、半径、
   折法都会丢弃这次待确认预览。
5. **原纸保护区**：在左侧面板用毫米坐标录入轴对齐矩形（x、y 为矩形左下角，
   原纸坐标系，至多 8 个），「添加保护区」后即绘入展开图（绿色虚线框，
   框内标注「保1」「保2」…序号），每条可单独删除。任一打孔点展开出的
   孔圆与任一保护区**相交或相切**即违规：状态栏指出原打孔点（折叠面坐标）、
   触碰的展开孔坐标及保护区编号，展开图不生成、下载按钮禁用；
   反查打孔的待确认结果同样判定（触碰保护区则返回具体原因、无法确认）。
   保护区必须完整位于原纸内：录入时越界会被拒绝；之后改小纸张尺寸导致
   既有保护区越界时，列表中该项标红并提示「请修正或删除」，修正或删除前
   不生成展开图、不能下载。
6. 右侧展开图中黑实线为纸张边界，灰虚线为全部折痕，红圆为孔，
   绿色虚线框为保护区；点击「下载展开 SVG」保存 `unfolded.svg`
   （独立文件，含 `mm` 尺寸标注，可直接用浏览器打开或送入激光切割/打印流程）。

### 折叠面视图的线型

- 黑色实线：纸张开口边（对应原纸边界）
- 蓝色虚线：折痕边（当前面在此处与下层相连）

## 含糊结果的处理（重要）

打孔若**压在折痕或纸张边界上**，展开后孔会横跨折痕/边界，产生“一个孔变成
半圆”等有歧义的结果。本应用不允许这种状态：

- 判定规则：孔心到最终折叠面**任意一条边**（无论它当前是开口边还是折痕边）
  的距离必须 **严格大于打孔半径 r**（另加 0.05mm 浮点容差）。
  几何上可证明：历次对折产生的所有折痕，最终都落在折叠面的边界上，
  因此这一条规则同时排除了“压任意历史折痕”与“压原纸边界”两类情况。
- 不满足时：问题孔在折叠面上标为橙色，下方给出具体中文提示
  （碰到的是哪条边、实际距离、需要多大间距），展开图不生成、下载按钮禁用，
  直到孔位被移入安全框。
- 反查打孔同样适用该判定：目标孔心距原纸边界或任一折痕不大于 r 时，
  接口返回具体原因（触及哪条边界/哪条折痕、实际距离），界面上不出现
  确认按钮，无法加入。
- 保护区判定：任一展开孔圆与任一保护区矩形相交**或相切**（圆心到矩形的
  最近距离 ≤ r，另加 0.05mm 容差）即违规，提示中指出原打孔点、触碰的
  展开孔与保护区编号；反查打孔的待确认结果执行同一判定。
- 折叠后纸面小到连打孔器直径都放不下时，同样直接报错提示。
- 重合孔位（例如两个不同的打孔点展开后位置重合）只绘制一次，并在状态栏注明
  合并数量。

## 接口

- `GET /`：页面
- `POST /api/unfold`：入参
  `{width, height, radius, folds: ["vR"|"vL"|"hT"|"hB", ...], points: [{x,y} 归一化], zones: [{x, y, w, h} 原纸 mm]}`，
  返回折叠面几何/SVG、折痕、孔数与展开 SVG；保护区越界或孔圆触碰保护区时
  `unfoldedSvg` 为 null，`error`/`zoneError` 给出具体原因
- `POST /api/reverse`：反查打孔。入参
  `{width, height, radius, folds, zones, target: {x, y}（原纸 mm 坐标）}`，
  返回折回最终折叠面的归一化孔心 `center`、本次打孔全部孔位 `holes`；
  目标点触及边界/折痕、保护区越界或连带孔触碰保护区时返回 400 与具体中文原因
- `POST /api/download`：同 `/api/unfold` 入参，合法时直接回传 `unfolded.svg` 文件
  （保护区违规时同样拒绝，返回 400）
- `GET /healthz`：健康检查

## 计算原理简述

- 每次对折沿当前面中线，对应尺寸减半；同时维护四条边的身份（开口/折痕）。
- 展开时按折叠顺序逆推，使用物理 mm 坐标：每逆推一层，静止层的点恒等映射，
  翻折层的点关于该层中线镜像，于是一个点每层最多产生两个前像，
  n 次折叠最多得到 2ⁿ 个原纸孔位，再按坐标去重。
- 反查是展开的正向逆映射：目标点每经过一次折叠，静止半不变、翻折半关于
  中线镜像，逐层折回后落在最终折叠面上；再对其做一次展开即得全部连带孔位，
  目标孔必在其中。
- 所有折痕展开后构成 (2^nv − 1) × (2^nh − 1) 的等分网格，直接绘为灰虚线。
- 保护区为原纸上的轴对齐矩形；孔圆与矩形是否相交/相切用「圆心到矩形的
  最近距离 ≤ 半径」判定（最近距离即圆心到矩形各边的 clamp 距离）。
  判定在去重前的全部展开孔上进行，因此能精确定位是哪一个打孔点的
  哪一个展开孔触碰了哪一个保护区。
